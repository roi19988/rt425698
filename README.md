# מבט לטבע — Nature Lens

אפליקציית Android ב־React Native / Expo, עם ארבעה מסכים בעיצוב בוטני, ממשק ומידע בעברית, עם יישור מימין לשמאל. הגרסה הראשונית כוללת צילום, בחירה מהגלריה, עד חמש תמונות של אותו פרט, מסך תוצאות, רמת ודאות, חלופות, אכילות, רעילות, שימושים מסורתיים וקישורי מקורות.

## מצב הפרויקט

קיים שרת פיתוח מקומי עם חיבור ל־Pl@ntNet לזיהוי אמיתי. המפתח נשמר בקובץ מקומי מוחרג מ־Git. Gemini מחובר ליצירת הסברים. כשהחיפוש אינו זמין נוצרים הסברים כלליים ללא אימות מקורות, ומידע האכילות והרעילות מסומן כלא מאומת. ללא כתובת שרת האפליקציה עוברת למצב הדגמה בדיוני. לא הופק APK. קיימים גילויים אחרונים ושמירה לאוסף במהלך ההפעלה; התמונות והתוצאות מוחזקות בזיכרון בלבד.

## הרצה

נדרש Node.js עם npm:

```sh
npm install
npm run typecheck
npm test
npm start
```

בחלון מסוף נוסף הפעילו `npm run server`. כתובת השירות המקומי: `http://localhost:4040/identify`. קובץ `.env` הוגדר לבדיקה בדפדפן המקומי. לשרת עצמו אין תלויות npm, ואפשר להפעילו ישירות ב־`node --env-file=server/.env server/index.cjs`.

לבדיקה בטלפון Android משתמשים ב־Expo Go התואם ל־SDK 55, או ב־APK מפרופיל `preview`. אפשר גם להריץ `npm run web` לתצוגה בדפדפן. הוראות מלאות ובטוחות לבדיקת מכשיר, שרת נגיש, RTL, TalkBack והרשאות נמצאות ב־[`docs/android-testing-he.md`](docs/android-testing-he.md).

לבניית APK לאחר הגדרת חשבון Expo:

```sh
npx eas-cli build --platform android --profile preview
```

לפני בניית APK יש להגדיר כתובת שרת HTTPS נגישה ב־`EXPO_PUBLIC_IDENTIFY_URL`; כתובת localhost נועדה לבדיקת הדפדפן בלבד ולא תעבוד בבניית APK. הפקת APK עשויה להיות תלויה במכסות ותמחור Expo. קובץ `eas.json` כולל פרופיל APK לבדיקה ופרופיל AAB לפרסום עתידי.

## חיבור זיהוי אמיתי

העתיקו `.env.example` ל־`.env` והגדירו `EXPO_PUBLIC_IDENTIFY_URL` לכתובת HTTPS של שרת הזיהוי, ואז הפעילו מחדש את Expo. המשתמש נדרש להסכים לשליחת התמונות לפני בקשת זיהוי. אין להכניס מפתחות Pl@ntNet או Gemini לאפליקציה: משתני `EXPO_PUBLIC_*` גלויים למשתמשים.

ראו `docs/backend.md` לחוזה השרת ולתכנון Pl@ntNet + Gemini. Pl@ntNet מחובר; Gemini מחובר בצד השרת. האפליקציה שולחת את התמונות הקיימות ואת התוצאה הקודמת כדי להוסיף ראיות לזיהוי של אותו פרט. כדי לזהות פרט אחר מתחילים זיהוי חדש.

## אימות

בדיקות Node בודקות תגובות חסרות, רמת ודאות שגויה, קישורי מקור לא בטוחים, סימון בטיחות כמאומתת ללא מקורות, פורמטי תמונות, טעויות מכסה והגנה מפני חשיפת מפתח בהודעות שגיאה. מצב אימות הבטיחות מוצג לצד מידע האכילות והרעילות ובנפרד מוודאות הזיהוי. עצם קיומו של קישור אינו מוכיח שטענת בטיחות נכונה: האימות המהותי צריך להתבצע בצד השרת מול מקורות מתאימים. כרגע אין תהליך אימות עצמאי, ולכן השרת ממשיך להחזיר `safetyVerified: false`.

בדיקת שירות אמיתית מול תמונת ההדגמה הציבורית של Pl@ntNet נעשתה גם ישירות וגם דרך השרת המקומי; המנוע החזיר `Hibiscus rosa-sinensis L.`. בדיקה זו מאמתת חיבור, ולא מודדת דיוק זיהוי במגוון צמחים. לא בוצעה עדיין בדיקת מצלמה והרשאות בטלפון Android אמיתי.
