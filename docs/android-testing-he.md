# בדיקת Nature Lens בטלפון Android

## הדרך המהירה: Expo Go

1. התקינו בטלפון Expo Go התואם ל־Expo SDK 55. אם גרסת Google Play אינה תואמת, הורידו גרסה מתאימה מ־`expo.dev/go` או השתמשו ב־APK המתואר בהמשך.
2. במחשב, מתוך תיקיית הפרויקט, הריצו `npm ci` ואחר כך `npx expo start`.
3. ודאו שהטלפון והמחשב מחוברים לאותה רשת Wi-Fi וסרקו ב־Expo Go את קוד ה־QR. אם חיבור LAN חסום, נסו `npx expo start --tunnel`; מצב Tunnel איטי יותר.
4. ללא כתובת שרת אפשר לפתוח את תוצאת ההדגמה, לבדוק את הממשק, RTL, תוויות הבטיחות, ניווט, מצלמה וגלריה. זיהוי אמיתי יישאר מושבת.

`localhost` בטלפון מצביע על הטלפון עצמו, לא על מחשב הפיתוח.

## חיבור שרת זיהוי לפיתוח

1. העתיקו `server/.env.example` אל `server/.env`. הגדירו שם בלבד את `PLANTNET_API_KEY` ואם נדרש את `GEMINI_API_KEY`. הקובץ מוחרג מ־Git.
2. לבדיקת Wi-Fi מקומית הוסיפו `HOST=0.0.0.0` ל־`server/.env`, הפעילו `npm run server`, ומצאו את כתובת ה־IPv4 הפרטית של המחשב, לדוגמה `192.168.1.25`.
3. העתיקו `.env.example` אל `.env` והגדירו `EXPO_PUBLIC_IDENTIFY_URL=http://192.168.1.25:4040/identify`. הפעילו מחדש את Expo. ודאו שחומת האש מאפשרת את החיבור רק ברשת פרטית מהימנה.
4. עבור APK או בדיקה מחוץ לרשת המקומית השתמשו בשרת HTTPS נגיש ומאובטח. אין להכניס מפתחות Pl@ntNet או Gemini לאפליקציה או למשתני `EXPO_PUBLIC_*`; כל ערך כזה גלוי בחבילת האפליקציה.

## יצירת APK באמצעות EAS Build

פרופיל `preview` הקיים ב־`eas.json` כבר מוגדר עם `distribution: internal` ו־`android.buildType: apk`, ולכן אין צורך בשינוי תצורה.

1. הגדירו כתובת HTTPS נגישה ב־`EXPO_PUBLIC_IDENTIFY_URL` בסביבת `preview` של EAS לפני הבנייה (למשל באמצעות `npx eas-cli env:set --environment preview --name EXPO_PUBLIC_IDENTIFY_URL --value https://example.test/identify --visibility plaintext`). זהו שינוי בחשבון הענן ויש לבצעו רק באישור בעל הפרויקט. אם רוצים APK לבדיקת ממשק בלבד, אפשר להשאיר אותה ריקה וזיהוי אמיתי יישאר מושבת.
2. התחברו לחשבון Expo באמצעות `npx eas-cli login`.
3. בבנייה הראשונה EAS עשוי לבקש לקשר או ליצור פרויקט EAS וליצור אישורי חתימה ל־Android. אלה שינויים בחשבון הענן ויש לאשר אותם כבעלי הפרויקט לפני שממשיכים.
4. הריצו `npx eas-cli build --platform android --profile preview`. הפעולה מעלה קוד ל־EAS ועשויה לצרוך מכסה; אין להריץ אותה ללא אישור בעל הפרויקט.
5. בסיום, פתחו בטלפון את קישור הבנייה או סרקו את קוד ה־QR, הורידו את ה־APK ואשרו התקנה ממקור זה. לחלופין, לאחר הורדת הקובץ למחשב, אפשר להתקין באמצעות `adb install path/to/app.apk`.

## רשימת בדיקות במכשיר

- עברית ו־RTL: כותרות, חצים, כרטיסים, שורות מעורבות בעברית/לטינית וגלילה ללא חיתוך.
- נגישות: הפעילו TalkBack ועברו ברכיבים לפי הסדר. ודאו שאזהרת הבטיחות מוקראת פעם אחת ובמלואה, כולל איסור אכילה, טעימה והאכלה לבעלי חיים; ודאו שכרטיסי אכילות ורעילות מוקראים כלחצנים ושמצב האימות אינו מוכרז פעמיים.
- טקסט מוגדל: בהגדרות Android הגדילו את גודל הגופן ואת גודל התצוגה לערכים הגבוהים, פתחו מחדש את האפליקציה ובדקו שאין חיתוך, חפיפה או תוכן שאי אפשר לגלול אליו.
- מצלמה וגלריה: בדקו אישור, דחייה וניסיון חוזר; בחרו/צלמו עד חמש תמונות; הסירו תמונה; ודאו שמיקרופון אינו מתבקש.
- בטיחות: בדקו את מצבי הבדיקה המאומת והלא־מאומת, שהאזהרה תמיד נראית, ושוודאות זיהוי אינה מוצגת כהוכחת בטיחות.
- זיהוי אמיתי: לאחר הגדרת שרת נגיש, אשרו במפורש שליחת תמונות ובדקו הצלחה, שרת לא זמין והודעת שגיאה ללא מפתחות או כתובות סודיות.

## תיעוד תקלה

צלמו מסך או הקלטת מסך באמצעות כלי Android. בדוח ציינו דגם מכשיר, גרסת Android, גרסת Expo Go או SHA של ה־APK, מצב TalkBack וגודל הטקסט, המסך והפעולות לשחזור, התוצאה הצפויה והתוצאה בפועל. טשטשו צמחים/מיקומים רגישים ואל תצרפו קובצי `.env`, מפתחות API או כתובות שרת פרטיות.
